# AWS deployment plan — October 18, 2026

Terraform was reinitialized from Git and the protected S3 state after CloudShell
discarded its temporary checkout, provider cache and Docker image. The complete
plan contains 24 additions, four tag updates and no deletions. It has not been
applied. The existing VPC, private subnets and operator security group are retained.

## Reviewed configuration

- EKS 1.35, reported in STANDARD_SUPPORT by the regional API.
- Private Kubernetes endpoint; public endpoint disabled.
- Two m7i-flex.large workers, each with two vCPUs and 8192 MiB memory.
- Encrypted 30 GB gp3 root disks, deleted on instance termination.
- IMDSv2 required, metadata response hop limit one.
- One NAT gateway and public IPv4 address for outbound connectivity; S3 gateway endpoint.
- Immutable-tag ECR repository with push scanning and AES256 encryption.
- EKS API, audit and authenticator logs with one-day retention.
- Existing operator role receives administration rights only in the demo cluster.
- HTTPS ingress to the cluster API from the operator security group.
- EKS service role and EC2 node role with the standard cluster, worker, CNI and
  registry-pull policies. CNI permissions remain on the node role for this demo.

The proposed cleanup deadline is 09:00 UTC (04:00 Chicago time). The ExpiresAt
tag records that deadline; it does not automatically stop or delete resources.
The temporary CloudShell policy expires separately at 09:30 UTC.

## Cost checks

AWS Pricing returned $0.09576 per On-Demand Linux m7i-flex.large instance-hour
in Northern Virginia. Two workers therefore cost $0.19152/hour before credits.
[EKS standard-support pricing](https://aws.amazon.com/eks/pricing/) adds
$0.10/cluster-hour. This $0.29152/hour subtotal excludes NAT, IPv4, disks, logs,
registry, data processing and transfer; it is not a total deployment estimate.
Free Tier eligibility metadata is true for the chosen instance type, but does not
guarantee launch capacity or make every supporting service free.

No successful AWS model-serving, recovery or scaling result follows from this
plan. Those require a successful apply and workload-level tests.
